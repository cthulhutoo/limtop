# v0.4.0 "Money View" Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Turn limtop from a recorder into a budget tool: canonical model identity, monthly cost projection with configurable budgets, and cache-waste analytics.

**Architecture:** All computation stays in the aggregator layer (`aggregator.rs` + a new `money.rs`); the TUI and JSON snapshot gain new panels/fields that render what the aggregator computes. Model aliasing happens at aggregator input (after provider parse, before grouping) so pricing lookups still see raw model strings — the `UsageEvent.model` field keeps the raw string, and `canonical_model()` maps it for display/grouping only. Cost is already computed per-event at provider parse time via `estimate_cost`, which consults the pricing override OnceLock — money.rs reads `e.cost`, never re-prices.

**Tech Stack:** Rust 1.97, ratatui, serde/serde_json, toml. No new deps.

**Baseline:** branch main @ `f60a8d9`, 32 tests green, clean tree. `cargo test` must stay green after every task.

### Task 1: model aliasing — `canonical_model()` in aggregator

**Objective:** One function maps raw model strings to canonical identity for by-model grouping and display, so `claude-sonnet-4-5-20250929`, `zai-org-glm-5-2`, etc. collapse to stable names.

**Files:**
- Modify: `src/aggregator.rs` (add `canonical_model` fn + use in `Dashboard::build`)
- Test: `src/aggregator.rs` (test module — check if one exists; if not, add)

**Design:**
```rust
/// Map raw model strings to canonical display identity. Grouping key AND
/// display name in one step. Unknown models pass through unchanged.
pub fn canonical_model(raw: &str) -> String {
    let s = raw.to_ascii_lowercase();
    // provider prefixes that wrap a model name: "zai-org-glm-5-2" → "glm-5.2"
    let stripped = s
        .strip_prefix("zai-org-")
        .or_else(|| s.strip_prefix("anthropic-"))
        .or_else(|| s.strip_prefix("google-"))
        .or_else(|| s.strip_prefix("openai-"))
        .unwrap_or(&s);
    let stripped = stripped
        .strip_suffix("-20250929")
        .or_else(|| stripped.strip_suffix("-20260301"))
        .unwrap_or(stripped);
    // version dots: "glm-5-2" → "glm-5.2"
    let dotted = stripped.replace("-5-2", "-5.2")
        .replace("-5-1", "-5.1")
        .replace("-4-7", "-4.7")
        .replace("-4-5", "-4.5")
        .replace("-4-6", "-4.6");
    dotted
}
```
Rule: strip known provider prefixes and date-version suffixes, dot the version segments. GPT-style ("gpt-5.2-turbo") passes through. This list lives in code, not config (YAGNI on config aliases for now — revisit if users ask).

**Behavior changes:** `by_model` keys become canonical. `UsageEvent.model` stays raw (pricing still keyed raw). `snapshot.rs` byModel uses the same canonical grouping (it re-aggregates from events — verify).

**Steps:**
1. Write failing tests: `canonical_model("claude-sonnet-4-5-20250929")` → `"claude-sonnet-4.5"`, `canonical_model("zai-org-glm-5-2")` → `"glm-5.2"`, `canonical_model("glm-4.7")` → `"glm-4.7"` (unchanged), `canonical_model("gpt-5.2-turbo")` → unchanged, `canonical_model("claude-opus-4-6")` → `"claude-opus-4.6"`.

### Task 2: money view — projection + budgets (`money.rs` + config)

**Objective:** Monthly projection ("at current burn, $X by month end") and per-project/month budgets from config, surfaced in dump/JSON/TUI.

**Files:**
- Create: `src/money.rs`
- Modify: `src/config.rs` (add `budgets: Option<BTreeMap<String, f64>>` — key is project name, value monthly USD), `src/main.rs` (mod money; compute + pass to dump/json/tui)
- Test: `src/money.rs` tests

**Design — `MoneyView`:**
```rust
pub struct MoneyView {
    pub month_spend: f64,          // USD this calendar month (all providers)
    pub projected_month: f64,      // month_spend + (daily_avg * days_remaining)
    pub daily_avg: f64,            // trailing 7d cost / 7 (0 if no history)
    pub days_remaining: u32,       // days left in current month
    pub budgets: Vec<BudgetLine>,  // per-project budget status
}
pub struct BudgetLine {
    pub project: String,
    pub budget: f64,
    pub spent: f64,
    pub projected: f64,
    pub over: bool,   // projected > budget
}
```

**Projection method:** `daily_avg = trailing-7d spend / 7` (7d because 30d spans include stale weeks; if zero trailing-7d events, fall back to trailing-30d/30). `projected = month_spend + daily_avg × days_remaining`. Calendar month via the existing `month_key` civil-date math (aggregator.rs:116 — reuse, or make it `pub(crate)`).

**Config schema:**
```toml
[budgets]
"~/claude/lantrn" = 50.0
"~/limtop" = 10.0
```
Parse like `pricing` (serde BTreeMap<String,f64>, optional). Budget key matches `UsageEvent.project` strings — document "must exactly equal the project path as shown in by project".

**Steps:**
1. Failing tests in `money.rs`: (a) `MoneyView::build` with 30d fixture: 7 events each $1 on the last 7 days + $5 earlier this month → `daily_avg ≈ 1.0`, `projected = month_spend + 1.0 × days_remaining`; (b) budget over: budget 10, spent 8, projected 12 → `over: true`; (c) no events → daily_avg 0, projection = month_spend; (d) days_remaining math: now = 2026-08-23 23:00 UTC → 8 days remaining.
2. Implement. civil_from_epoch helper for `days_remaining` (reuse month_key math: days in month − current day).
3. `cargo test` green → wire config: `budgets` field + parse test ("[budgets] table parses").
4. `main.rs`: after Dashboard build, `let money = money::MoneyView::build(&reg.events, &now, cfg.budgets());` — pass `&money` into dump_report, dump_json (snapshot gains `money: {monthSpend, projectedMonth, dailyAvg, daysRemaining, budgets:[{project,budget,spent,projected,over}]}`), and TUI.
5. Commit `feat: monthly projection + per-project budgets`.

### Task 3: cache-waste panel (`CacheStats` in aggregator or money.rs)

**Objective:** Cache hit rate and "re-warmed dollars" per project — the analytics nobody else has.

**Definition:** hit rate = cache_read / (cache_read + input) per project. "Cache-waste dollars" = dollars spent on cache_creation where a read of already-cached context should've served — approximated as: sum over events of `cache_creation_tokens × cache_write_mult` (1.25) for tokens that were re-created within the same session (proxy: cache_creation > 3× the event's input tokens is "re-warming a large context"; this is a heuristic and gets labeled "est."). Keep it honest: panel title says `cache · estimated`.

**Files:**
- Modify: `src/aggregator.rs` (CacheStats struct + per-project computation in build, or separate fn `cache_stats(events) -> Vec<(String, CacheStats)>`)
- Modify: `src/tui/mod.rs` (panel), `src/snapshot.rs` (JSON), `src/main.rs` dump_report
- Test: `src/aggregator.rs`

**Design:**
```rust
pub struct CacheStats {
    pub hit_rate: f64,       // 0..1
    pub reads: u64,          // cache_read tokens
    pub writes: u64,         // cache_creation tokens
    pub rewarm_dollars: f64, // estimated $ from avoidable re-warming
}
```
`rewarm_dollars`: for each event where `cache_creation > 3 * input_tokens`: `rewarm_dollars += (cache_creation - 3*input) * input_price/1M * 1.25` (input price via existing pricing fn — but pricing is per-model; use the event's price). Store per-project, top 5 by rewarm_dollars.

**Steps:**
1. Failing tests: (a) hit_rate: 1 event, cache_read=90, input=10 → 0.9; (b) rewarm: input=1k, cache_creation=10k → rewarm on (10k−3k)=7k × price; (c) no-cache events → hit_rate 0 (or None — decide: 0 when denominator 0; document).
2. Implement `cache_stats` in aggregator.
3. Panel in TUI (compact table under projects, or merge into a new "cache" tab — simplest: new panel when span ≥ Week), snapshot + dump fields `byProjectCache`.
4. Commit `feat: cache analytics — hit rate + estimated re-warm dollars`.

**Verification:** live `--dump --all` shows cache panel with real numbers; hit rates 0..1.
